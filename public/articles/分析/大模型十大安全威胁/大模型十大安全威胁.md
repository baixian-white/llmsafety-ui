# 大模型十大安全威胁全解析（OWASP Top 10 LLM - 2025）

人工智能大模型在 2025 年已经无处不在：从办公助手到代码生成器，从医疗问诊到司法辅助。但在光鲜的应用背后，一张隐形的“风险清单”正在悄然展开。
OWASP（开放 Web 应用安全项目）从 2023 年起针对大模型应用发布 Top 10 榜单，旨在帮助开发者、研究人员与监管者直面 AI 的独特安全挑战。2025 年版本更是揭示出一幅复杂的风险谱图。（附录一为OWASP Top 10 LLM-2025安全风险与防护策略清单）

这十大威胁并非孤立存在，而是沿着大模型 **数据流与应用链条** 逐步蔓延，从训练、部署到交互，每一环都可能成为突破口。下面，我们逐一解析。

## 1. 提示词注入（LLM01 Prompt Injection）

**风险描述**
攻击者在输入中植入恶意指令，诱导模型绕过安全规范，甚至访问未授权的系统资源。手法包括代码注入、对抗性后缀、多语言混淆、跨模态注入等。

**典型场景**

* 用户输入中隐藏“后门命令”，迫使模型泄露数据库信息。

* 对话中混杂多语种提示，让模型绕开过滤。

**防护思路**

* 严格约束模型行为，定义清晰的输入输出格式；

* 对高风险操作引入人工审批；

* 加强外部内容隔离与红蓝对抗演练。

## 2. 敏感信息泄露（LLM02 Sensitive Info Disclosure）

**风险描述**
大模型可能在交互或训练过程中暴露隐私，包括个人信息（PII）、商业机密，甚至自身的内部数据。

**典型场景**

* 工程师不小心将客户隐私数据混入训练集；

* 模型在回答时无意暴露内部 API 密钥。

**防护思路**

* 加强数据清洗与最小化采集；

* 建立严格的访问控制与日志审计机制。

## 3. 供应链风险（LLM03 Supply Chain）

**风险描述**
当模型依赖开源框架、第三方插件或硬件时，任何一环的不安全都可能引入连锁风险。

**典型场景**

* 使用了存在漏洞的开源依赖；

* 采用许可模糊的外部模型，埋下法律风险；

* 边缘设备运行模型时被恶意固件篡改。

**防护思路**

* 对组件进行漏洞扫描与许可证审计；

* 使用可追溯来源的模型；

* 对端侧模型进行加密与安全测评。

## 4. 模型数据投毒（LLM04 Model Data Poisoning）

**风险描述**
恶意数据被注入训练集，导致模型输出被操控，甚至形成偏见或后门。

**典型场景**

* 攻击者在公开论坛发布“污染数据”，影响模型微调效果；

* 知识库被注入虚假事实，模型输出错误信息。

**防护思路**

* 验证数据合法性与来源；

* 实施版本化的数据集管理；

* 利用 RAG 增强与红蓝对抗识别异常。

## 5. 不当输出处理（LLM05 Improper Output Handling）

**风险描述**
当模型生成的输出被系统“直接使用”时，风险往往成倍放大。

**典型场景**

* 将 LLM 生成的 SQL 未经处理直接执行 → SQL 注入；

* 生成的 HTML/JS 被浏览器渲染 → XSS 攻击；

* 模型输出被拼接进文件路径 → 路径遍历。

**防护思路**

* 对模型输出进行编码与验证；

* 制定内容安全策略（CSP）；

* 加强运行时日志与监控。

## 6. 过度代理（LLM06 Excessive Agency）

**风险描述**
当大模型或 Agent 获得过高权限，甚至能自主操作外部系统时，风险指数级上升。

**典型场景**

* Agent 除了能读文档，还能删除修改；

* 自主执行数据库操作而无人工干预。

**防护思路**

* 权限最小化；

* 引入用户审批环节；

* 对输入输出进行严格清理。

## 7. 系统提示泄漏（LLM07 System Prompt Leakage）

**风险描述**
系统内部提示（System Prompt）如果泄露，攻击者可能推测业务逻辑或安全策略。

**典型场景**

* 泄露内部规则（如“屏蔽所有股票推荐”）；

* 透露权限结构或数据库类型。

**防护思路**

* 分离敏感数据；

* 对提示词做严格控制与审查；

* 设置外挂防护与安全监控。

## 8. 向量与嵌入漏洞（LLM08 Vector & Embedding Weakness）

**风险描述**
向量数据库与嵌入机制本身存在新型漏洞，可能导致跨用户信息泄露或数据被反演。

**典型场景**

* 多租户共享同一知识库，被越权访问；

* 攻击者通过嵌入反演还原原始文本。

**防护思路**

* 严格权限与访问控制；

* 对数据分类与质量进行审查；

* 全链路日志与异常监控。

## 9. 信息误导（LLM09 Misinformation）

**风险描述**
大模型的“幻觉”问题仍然严重：输出看似合理，却事实全错。

**典型场景**

* 生成虚假的法律条款；

* 提供不安全的编程示例；

* 在医疗问答中给出错误诊断。

**防护思路**

* 引入增强检索生成（RAG）；

* 跨源验证输出；

* 提示用户“AI 生成”标签，降低过度信任风险。

## 10. 无限资源消耗（LLM10 Unbounded Consumption）

**风险描述**
攻击者通过“拖垮”模型资源，使服务降级甚至瘫痪。

**典型场景**

* 海量垃圾请求 → 接口层拒绝服务；

* 超大上下文输入 → 内存溢出；

* 高复杂度计算 Prompt → 资源耗尽；

* 利用按量计费机制，制造“钱包拒绝服务”。

**防护思路**

* 设置输入验证与速率限制；

* 对任务执行超时与节流；

* 引入 AI 水印与调用跟踪。

## 总结：风险的交织与防护的整体性

十大风险可以分为三类：

1. **模型固有缺陷**（如幻觉导致的信息误导）；

2. **攻击者主动利用**（如提示词注入、数据投毒、不当输出处理）；

3. **外部生态带来的新风险**（如供应链、过度代理、嵌入漏洞）。

这些威胁并非彼此独立，而是相互叠加、交织。例如，**提示词注入可能引发信息泄露**，**数据投毒可能放大幻觉误导**。
因此，有效的安全防护需要“纵深防御”——从输入过滤到输出验证，从训练数据到系统插件，形成一张全链路的安全网。

OWASP 的 Top 10 并不是“最终答案”，而是提醒业界：
**大模型安全不是某一方的责任，而是整个生态的博弈。**
