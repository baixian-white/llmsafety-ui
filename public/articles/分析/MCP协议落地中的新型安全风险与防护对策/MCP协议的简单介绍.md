# &#x20;MCP 的简单介绍

## 一、什么是 MCP？

MCP（Model Context Protocol，大模型上下文协议）由 Anthropic 等机构提出，旨在为大模型构建一个 **统一的上下文与外部交互标准**。如果把大模型比作“大脑”，那么 MCP 就是它的“操作系统接口”，负责连接外部世界的数据和工具。它的意义在于：让大模型不再是一个“孤立的对话体”，而是真正能够与环境互动、完成复杂任务的智能体。

**核心能力包括：**

1. **多模态上下文接入**：不仅理解用户输入，还能实时调用邮件、文档、数据库、网页等外部信息，构建“全景上下文”。

2. **工具调用与任务执行**：模型可通过 MCP 像调用 API 一样执行操作，例如发邮件、查资料、运行脚本。

3. **上下文缓存与记忆**：支持长期记忆与对话历史缓存，提升模型的持续交互能力。

与 Function Calling 相比，MCP 更像是一个“协作协议”而非单一功能接口。它不仅能调用函数，还能管理多轮上下文、支持多模态，并内置权限与安全机制。

Function Calling 与 MCP 对比表

| 对比维度        | Function Calling                             | MCP                                 |
| ----------- | -------------------------------------------- | ----------------------------------- |
| **提出者**     | OpenAI、Google 等大模型厂商                         | Anthropic（Claude）提出，正在推动标准化         |
| **核心作用**    | 让模型能够调用函数/API 执行具体任务                         | 建立模型与外部数据源、工具、上下文的标准交互协议            |
| **本质**      | 一种“模型调用函数”的能力增强方式                            | 一种标准化的模型与外部环境之间的桥梁协议                |
| **支持的功能类型** | 单次函数调用（如查天气、发邮件）                             | 函数调用 + 多轮上下文接入 + 工具集成 + 状态管理        |
| **上下文管理**   | 无内置上下文管理，用户需手动维护                             | 内置“根（root）”机制，可组织完整上下文并缓存           |
| **能力范围**    | “单步执行”或“问一下就走”型能力                            | “任务流执行”或“持续对话、记忆协作”型能力              |
| **安全性设计**   | 通常需自己保障函数安全，如 token 控制、参数校验等                 | 内置权限、上下文验证、数据隔离、内容可控等机制             |
| **实际场景**    | 适用于轻量插件、问答任务、独立函数调用                          | 适用于 AI Agent、多轮复杂任务、与企业系统深度协同的智能体场景 |
| **是否支持多模态** | 部分支持（要看实现）                                   | 原生支持多模态上下文，如图像、文档、网页                |
| **典型代表**    | ChatGPT 插件、GPT Function Calling、Gemini Tools | Claude 3 系列、Anthropic MCP SDK       |

## 二、MCP 带来的新型安全风险

随着 MCP 在智能体（AI Agent）和企业级应用中的落地，新的安全问题逐渐暴露出来。这些风险比传统 LLM 更复杂，因为它们不仅涉及文本生成，还包括外部系统调用与多方协作。

### 1. 内容可控性风险

* **内容污染**：外部上下文可能被植入恶意指令，诱导模型泄露信息或执行危险操作。

* **越权调用**：模型在上下文误导下可能调用删除/修改数据库的命令。

* **上下文篡改**：攻击者修改对话缓存或任务上下文，使模型偏离原始意图。

**应对措施**：

* 上下文过滤与参数校验，剔除可疑输入；

* 隔离用户输入、系统提示与外部上下文，防止混淆；

* 引入人工审核机制，对高危任务进行“人类把关”；

* 速率限制 + 输出监控，实时发现异常操作。

### 2. 数据安全风险

* **数据泄露**：敏感信息（隐私、商业机密）可能通过 MCP 被不当暴露。

* **未授权访问**：若凭证被盗，攻击者可冒充合法客户端获取全部数据（“钥匙串风险”）。

* **隐私合规**：缺乏用户同意机制可能违反 GDPR 等隐私法规。

**应对措施**：

* 严格数据隔离与最小化原则，只传输必要数据；

* 端到端加密 + 安全存储凭证；

* 不直接向模型暴露密钥，由服务器中转请求；

* 细粒度用户同意机制，确保合规；

* 审计日志与异常监控，支持事后追踪。

### 3. 权限管理风险

* **上下文越权**：多用户环境下，某人可能调用他人上下文数据。

* **篡改共享上下文**：攻击者修改缓存的模板或知识库，影响后续模型决策。

* **信任边界缺失**：一个 MCP 节点若未分隔权限，可能被利用跨系统提升权限。

**应对措施**：

* 基于 RBAC 的细粒度权限控制；

* 请求与数据签名校验，确保来源可信；

* 上下文完整性验证（哈希比对）；

* 多租户隔离，确保不同用户上下文不交叉；

* 定期权限审核，遵循最小权限原则。

### 4. 其他潜在风险

* **模型行为操控**：攻击者利用提示链让模型逐步偏离安全轨道。

* **对抗性攻击**：包括提示逃逸、多模态干扰输入等。

* **工具/环境漏洞**：MCP 集成的数据库、脚本工具或运行环境若存在漏洞，可能被攻击者利用。

**应对措施**：

* 沙箱与容器隔离环境，限制模型可调用资源；

* 利用可信执行环境（TEE），构建硬件级安全区；

* 多模态交叉校验 + 意图识别，监控模型是否“跑偏”；

* 对工具进行安全加固、定期打补丁、漏洞扫描；

* 建立渗透测试与红蓝对抗机制，提前发现薄弱环节。

## 三、总结与展望

MCP 协议的出现，让大模型真正拥有了“行动力”，能够从数据消费转向任务执行。然而，这种能力扩展的背后，也伴随着安全边界的不断扩大。内容污染、数据泄露、权限越权、工具漏洞……这些风险提醒我们：**MCP 的落地不能只谈功能，还必须同步构建防护体系。**

MCP 安全风险与防护措施总结表

| 安全风险      | 可能表现                                                                     | 防护措施                                                                                                                                                   |
| --------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **内容可控性** | 1. 上下文含恶意指令，模型输出不当言论2. 模型被诱导执行未授权操作                                      | 1. 提示过滤与参数校验                            2. 区分用户内容和系统提示，防止混淆 3. 人工审核关键提示/结果4. 限制模型调用频率，监控异常模式                                                           |
| **数据安全**  | 1. 敏感数据通过上下文泄露给无关方     2. 攻击者窃取令牌获取用户全部数据                                | 1. 本地化部署或联邦学习，避免裸数据上云                                                           2. 通信加密和凭据加密存储                    3. 严格认证授权，隔离不同用户数据4. 审计数据访问，及时发现泄露迹象 |
| **权限管理**  | 1. 未授权用户调用他人上下文资源        2. 恶意修改共享上下文导致错误响应                              | 1. RBAC 等细粒度权限控制                     2. 请求/数据签名校验，确保来源可信   3. 上下文完整性验证（哈希比对）        4. 多租户隔离，最小权限配置                                                    |
| **其他风险**  | 1. 组合提示逐步操控模型决策               2. 对抗样本让模型逃逸安全规则           3. 工具漏洞被利用，攻击系统 | 1. 沙箱隔离执行环境                               2. 利用 TEE 保护代码和敏感数据          3. 意图识别监控 AI 行为偏差                 4. 加强工具输入校验与漏洞修补                              |

未来，行业可能会在以下方向展开探索：

1. 制定 **MCP 安全标准**，为不同厂商提供统一的安全规范；

2. 引入 **责任认定机制**，明确 AI 失控时的责任边界；

3. 开发 **AI 行为监管工具**，实时监控智能体行为偏差；

4. 将 **隐私计算、TEE、沙箱** 等前沿技术引入 MCP 架构。

**一句话总结：MCP 打开了大模型的新边界，但安全将决定它能走多远。**
