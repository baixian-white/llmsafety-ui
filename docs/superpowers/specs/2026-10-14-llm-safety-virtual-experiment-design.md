# 大模型安全攻防与可信评测虚拟仿真实验设计

## 1. 建设目标

在现有“大模型安全交互式教学平台”中新增独立的“虚拟仿真实验”模块，将已有越狱、幻觉、对抗测试、安全数据集、防御知识和政策资源组织为一个可直接访问、可连续操作、可自动评分、可生成实验报告的综合设计型实验。

本期交付定位为申报演示版，面向网络空间安全、信息安全专业本科生。模型响应全部来自预设案例和确定性仿真规则，不调用真实大模型 API；页面必须明确标注“虚拟仿真响应”与“教学演示数据”，不得将演示数据表述为真实教学成效。

## 2. 项目定位

- 项目名称：大模型安全攻防与可信评测虚拟仿真实验
- 申报方向：未来信息
- 实验类型：综合设计型
- 学习对象：网络空间安全、信息安全专业本科生
- 实验任务：完成待测大模型的基线测试、越狱测试、幻觉测试、提示词注入测试、防御配置、复测比较和综合安全结论
- 仿真方式：预设案例库、参数分支、规则评分、知识库反馈和学习分析
- 教学产物：实验过程记录、综合评分、能力画像、风险矩阵和实验报告

## 3. 建设边界

### 3.1 本期包含

1. 独立实验首页和固定实验入口。
2. 实验准备、前测和知识资源推荐。
3. 七阶段、32个实质性交互步骤。
4. 普通网站教程式高亮引导。
5. 不同选项产生不同响应、指标、反馈和得分。
6. 防御策略配置及防御前后复测。
7. 本地实验进度保存和恢复。
8. 过程评价、结果评价、五维能力画像。
9. 可打印或另存为 PDF 的实验报告。
10. 明确标注演示数据的教师看板。
11. 首页、导航、404页面和关键路由修复。
12. Chrome、Edge 所对应 Chromium 内核下的响应式验证。

### 3.2 本期不包含

1. 真实大模型 API 调用。
2. 真实学生、班级和教师账号系统。
3. 服务端数据库持久化。
4. 真实教学成效数据。
5. “实验空间”2026版接口联调。
6. 二级等保测评、正式并发承诺和软件著作权办理。

上述未包含事项须在申报材料中按实际状态填写，不得以演示功能替代证明材料。

## 4. 信息架构

| 路由 | 页面 | 作用 |
|---|---|---|
| `/experiment` | 实验首页 | 展示定位、目标、七阶段、开始与继续入口 |
| `/experiment/prepare` | 实验准备 | 展示任务书、仿真边界、前测与知识推荐 |
| `/experiment/run` | 实验操作台 | 承载七阶段32步操作、教程引导和过程记录 |
| `/experiment/result` | 实验结果 | 展示得分、指标、风险矩阵和扣分原因 |
| `/experiment/report` | 实验报告 | 展示能力画像、过程摘要并支持打印 |
| `/experiment/dashboard` | 教师演示看板 | 使用明确标注的演示数据呈现教学统计 |

顶部导航增加高辨识度的“虚拟仿真实验”入口。现有测试平台、解决方案、研究、数据集和政策页面继续保留，作为拓展学习资源。

## 5. 视觉设计

新增模块沿用现有平台的紫蓝科技风格和明暗主题，不另建不相容的视觉体系。

- 主色：品牌紫 `#5830D6`，辅色为靛蓝、青色。
- 背景：浅色灰白网格；深色使用 `#0A071A` 附近底色及低透明度光晕。
- 容器：半透明卡片、细边框、轻阴影、适度毛玻璃。
- 字体：沿用系统无衬线字体栈。
- 状态色：绿色表示通过，琥珀色表示关注，红色表示高风险，紫色表示当前实验步骤。
- 动效：仅使用淡入、进度变化、引导脉冲和轻微悬浮；尊重 `prefers-reduced-motion`。
- 响应式：桌面端三栏操作台；窄屏转为单栏并将阶段导航折叠为横向进度条。

## 6. 实验流程

### 阶段一：任务准备（步骤1—4）

选择待测模型、识别关键资产、确定测试范围、完成实验前测。

### 阶段二：基线测试（步骤5—8）

选择基线数据集、配置模型约束、执行正常问题测试、评价响应质量与安全性。

### 阶段三：越狱攻击测试（步骤9—13）

选择攻击方法、组合提示词结构、设置攻击强度、判定是否越狱、标注违规类型并形成攻击成功率。

### 阶段四：幻觉风险测试（步骤14—18）

选择测试场景、配置诱导条件、执行仿真、对照证据标记错误并计算幻觉率与可信度。

### 阶段五：提示词注入与对抗测试（步骤19—22）

选择注入方式、配置载荷和位置、执行仿真、判断提示泄露、敏感信息暴露或权限越界。

### 阶段六：安全防御与复测（步骤23—28）

配置输入检测、提示保护、输出过滤和风险阈值，使用相同样本复测并在安全性与可用性之间进行权衡。

### 阶段七：综合评价（步骤29—32）

完成风险矩阵、给出是否通过测试的结论、提交安全改进建议、生成得分和报告。

每个步骤均包含输入、操作、系统反馈、知识库作用、产业测试任务映射和评分依据。页面加载、阅读说明和点击“下一步”不计入32个实质操作步骤。

## 7. 教程引导

教程引导采用普通网站常见的新手引导形式：

1. 首次进入操作台自动开启。
2. 当前操作卡出现紫色高亮边框和脉冲标记。
3. 浮动气泡说明当前任务、操作原因和完成条件。
4. 遮罩仅弱化无关区域，不阻断当前表单操作。
5. 当前步骤未形成有效输入时，“完成当前操作”按钮保持禁用。
6. 完成操作后展示即时反馈，学生确认后进入下一步。
7. 支持上一步、退出引导和重新开启引导。
8. 刷新页面后恢复步骤、答案、得分和用时。

## 8. 仿真数据与分支逻辑

实验数据由以下五类静态数据组成：

1. 仿真模型档案：能力特点、安全边界和已知风险。
2. 风险案例：越狱、幻觉、注入和敏感信息案例。
3. 响应分支：按模型、攻击方式、强度和防御配置组合返回结果。
4. 知识反馈：每个选项对应原理解释、风险说明和修正建议。
5. 评分规则：正确性、完整性、策略质量、提示使用和复测改善幅度。

仿真引擎必须为确定性计算，同一组输入产生同一组结果，便于教学复现与申报演示。不同选择至少影响即时反馈、得分、风险指标和最终能力画像中的两项。

## 9. 评分与能力画像

总分100分：

| 维度 | 分值 |
|---|---:|
| 实验准备与风险识别 | 10 |
| 基线测试 | 10 |
| 越狱攻击测试 | 20 |
| 幻觉风险测试 | 15 |
| 提示词注入与对抗测试 | 15 |
| 防御配置与复测优化 | 20 |
| 综合结论与改进建议 | 10 |

过程评价记录选择、参数、错误次数、提示次数、用时和完成状态；结果评价记录攻击识别、防御效果、风险结论和建议质量。提示不会阻止实验完成，但会降低“自主分析”相关得分，且单步提示扣分设置上限，避免学生因使用教学帮助而失去主要成绩。

能力画像包含五个维度：风险识别、攻击设计、响应分析、防御配置、综合决策。各维度由指定步骤的归一化得分计算，不生成无法追溯的黑箱结论。

## 10. 知识库与智能辅助

本期不声称使用生成式大模型实时推理。智能辅助由现有大模型安全知识库、步骤规则和学习分析共同完成：

- 实验前：根据前测薄弱项推荐知识主题。
- 实验中：根据选择匹配风险解释、纠错提示和相关知识入口。
- 实验后：根据步骤得分与提示记录生成能力短板和学习建议。

申报材料中统一使用“预设案例仿真”“知识库辅助”“规则驱动学习分析”等准确表述。

## 11. 状态与数据流

演示版将实验状态保存在浏览器 `localStorage`，状态版本号为 `v1`。核心状态包括实验开始时间、当前步骤、步骤答案、提示使用、步骤反馈、前测结果和完成时间。

数据流为：

`步骤定义 → 学生输入 → 输入校验 → 仿真反馈 → 评分计算 → 本地保存 → 指标汇总 → 能力画像/实验报告`

状态解析失败、版本不匹配或数据缺失时，系统应提示“实验记录无法恢复”，保留用户主动重新开始的入口，不出现空白页。

## 12. 报告与教师看板

实验报告展示项目名称、仿真环境、七阶段摘要、关键选择、防御前后指标、风险结论、分项成绩、能力画像和学习建议。打印样式隐藏导航和操作按钮，适配 A4 纵向输出。

教师看板使用固定演示数据，页面顶部和统计区域均标注“教学演示数据”。看板用于展示未来教学管理能力，不得在申报书中写成已经发生的教学人数或成效。

## 13. 错误处理与可访问性

- 所有按钮具有可读文本或 `aria-label`。
- 表单选项支持键盘操作和清晰焦点样式。
- 状态反馈不只依赖颜色，同时使用图标和文字。
- 未完成当前步骤时说明缺少的操作，不静默禁用。
- 直接访问结果或报告而无实验记录时，展示演示结果入口与返回实验入口。
- 未匹配路由进入统一404页面。
- 打印失败不影响页面查看，可提示使用浏览器打印功能。

## 14. 验证标准

1. `npm run typecheck` 通过。
2. `npm run test` 中评分、状态恢复、指标计算测试通过。
3. `npm run build` 通过。
4. `/experiment` 可直接进入实验。
5. 操作台存在32个可追踪的实质步骤。
6. 当前步骤未完成时不能进入下一步。
7. 至少三组不同策略能产生不同得分和指标。
8. 刷新页面后可恢复实验进度。
9. 结果页、报告页和看板可独立展示演示数据。
10. Chromium桌面宽屏和窄屏视口无关键内容溢出。
