# 大模型安全虚拟实验对话工作台重构设计

## 1. 目标与边界

本次重构不改变“七阶段、32个实质操作、100分过程评价”的实验骨架，而是把越狱、幻觉、提示词注入和防御复测中的执行环节，改造成与原测试平台一致的真实聊天操作形态。

学生应实际完成以下闭环：选择模型和原平台案例，查看原始问题，编辑测试提示词，点击发送，在多轮对话中观察仿真模型响应，选取证据片段，作出安全判定，配置防御，再使用同一案例复测并比较前后结果。

“真实对话”指真实的聊天交互、发送过程、消息记录和判定操作；模型回答仍来自仓库现有 `public/TestResult` 案例和确定性防御分支，并明确标注“预设案例仿真响应”，不调用外部大模型 API。

## 2. 方案比较与选择

### 方案A：直接嵌入整个原测试平台页面

优点是外观和逻辑复用最多。缺点是原页面超过千行，内部状态与实验32步、评分和本地持久化高度耦合困难，且会把实验引导、证据评分和阶段导航挤到页面之外。

### 方案B：复制原页面聊天代码到实验页

优点是改动快。缺点是复制异步流程、消息结构和防御逻辑后会形成两套实现，原测试平台后续修复无法同步，重复代码也难以测试。

### 方案C：案例适配层 + 独立实验对话工作台（采用）

把原平台 JSON 结构、模型目录和防御测试链抽成纯 TypeScript 适配层；实验页使用新的对话工作台组件消费统一案例。这样能复用同一批案例和核心判定规则，又能保留实验步骤、评分、教程和证据标注。

## 3. 页面布局

实验操作页继续使用现有三栏结构，但执行型步骤切换为“对话模式”：

- 左栏保留七阶段导航，并显示当前案例、模型和复测状态。
- 中栏顶部显示当前实质操作与教程引导。
- 中栏主体为对话工作台：模型/案例选择区、原始问题卡、消息流、可编辑提示词输入框、发送按钮和仿真标识。
- 右栏改为实验记录与证据判定区：可选证据片段、风险标签、学生结论和防御前后摘要。
- 非执行型步骤继续使用单选、多选、滑块和文本控件，不为所有32步强行套用聊天界面。

聊天视觉直接继承原测试平台的用户右侧紫色气泡、模型左侧中性色气泡、安全警告红色、幻觉纠错橙色和防御成功蓝色语义，同时统一到实验模块已有的圆角、阴影、暗色模式与紫靛渐变。

## 4. 案例与数据适配

新增案例适配器，运行时读取原平台已有文件：

- `/TestResult/jailbreak/{model}.json`
- `/TestResult/halluc/{model}.json`

统一案例包含 `id`、`category`、`modelId`、`question`、`prompt`、`baselineResponse`、`referenceAnswer`、`correctedResponse` 和 `defenseTests`。越狱案例优先使用 `prompt` 作为发送内容；幻觉案例使用 `question`。提示词注入实验复用原越狱案例中包含指令覆盖、角色伪装和安全规则绕过特征的样本，并以实验标签说明其注入特征，不伪造新的在线结果。

如果网络加载失败，工作台显示明确错误和“重新加载案例”按钮，不自动退回虚构响应。已加载案例保存在当前实验状态中，刷新后仍可恢复已发送提示词、响应摘要和判定记录。

## 5. 对话状态与确定性回复

每次运行形成一个 `ConversationRun`，记录阶段、模型、案例、学生实际发送文本、是否开启防御、消息列表、响应状态、证据选择和安全判定。

发送流程为：

1. 学生选择模型和案例，系统填入原平台提示词。
2. 学生可编辑提示词；空白内容不能发送。
3. 点击发送后立即写入用户消息，并显示“正在生成仿真响应”。
4. 无防御时返回案例原始响应。
5. 有防御时依次展示原案例 `tests` 中的防御链；若命中拦截，返回对应防御输出；幻觉案例存在 `response_new` 时返回纠正后回答。
6. 系统根据原案例和防御结果生成可选证据片段，但不替学生自动完成判定。
7. 学生至少选取一条证据并作出判定后，才满足对应实验步骤的完成条件。

流式效果按字符批量更新，但不使用随机回复内容。停止、切换案例或重置时通过运行标识取消旧任务，避免旧响应写入新对话。

## 6. 32步映射

实验总步数和分值不变，核心交互按阶段映射：

- 基线测试：模型与案例选择、发送基线提示词、阅读响应、记录基线风险。
- 越狱测试：选择原越狱案例、编辑攻击提示词、发送并查看响应、标注越狱证据、作出攻击是否成功的判断。
- 幻觉测试：选择原幻觉案例、发送问题、对照参考答案、标注事实错误、判断幻觉类型和风险。
- 提示词注入：选择具有指令覆盖特征的原案例、编辑载荷、发送、标注被覆盖的目标与泄露证据。
- 防御复测：配置输入/模型/输出层防御，锁定同一案例与同一提示词重新发送，展示防御链和响应，再比较安全性与可用性。
- 综合评价：沿用风险矩阵、结论、改进建议与报告生成。

案例选择和发送动作会写入实验答案；证据与判定仍由现有评分引擎计分。只有实际完成发送并得到响应，相关“执行测试”步骤才可继续，不能仅点击下一步。

## 7. 组件与文件边界

- `caseAdapter.ts`：原平台模型目录、JSON类型校验、案例适配、注入特征筛选。
- `conversationEngine.ts`：纯函数生成无防御/有防御结果、证据候选和对比摘要。
- `useExperimentConversation.ts`：案例加载、运行取消、消息流和与实验状态同步。
- `ExperimentConversationWorkbench.vue`：聊天工作台主体。
- `ConversationEvidencePanel.vue`：证据选择、安全判定与前后对比。
- `ExperimentRun.vue`：决定当前步骤显示普通控件还是对话工作台，不承载案例解析细节。

纯逻辑必须先写单元测试；Vue组件只负责渲染和事件转发。

## 8. 教程引导

教程仍是一般网站式浮层引导，但在对话步骤中依次聚焦案例选择、提示词编辑、发送按钮、模型回复、证据选择和安全判定。引导只解释，不代替点击和输入。未发送、未获得响应或未完成证据判定时，完成按钮保持禁用并说明缺失动作。

## 9. 验证标准

1. 原测试平台的六个模型与越狱/幻觉 JSON 均可通过适配器加载。
2. 至少一个越狱案例和一个幻觉案例可在实验页完成选择、编辑、发送、响应、证据和判定闭环。
3. 防御复测使用同一模型、同一案例和同一发送文本，防御链来自原案例 `tests`。
4. 无防御与有防御响应、状态和指标可形成可追溯对比。
5. 刷新后保留会话记录；重置后清除实验会话。
6. 页面持续明确标注“预设案例仿真响应”，不声称连接在线模型。
7. 现有32步、100分、报告、能力画像和教师演示看板继续有效。
8. 单元测试、类型检查和生产构建通过；桌面、移动、明暗主题无关键交互溢出。

## 10. 设计确认说明

本设计依据用户已明确确认的方向直接进入实施：复用原测试平台交互逻辑和案例，采用大模型聊天式真实操作，同时继续使用预设模拟数据。用户已要求后续不再逐项确认，因此本轮不设置额外设计评审停顿。
